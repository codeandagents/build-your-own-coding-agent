## Step 2: Claude Code's rules

From Claude Code's tools reference ([code.claude.com/docs/en/tools-reference](https://code.claude.com/docs/en/tools-reference),
"Output limits" and "Large files"):
- **Bash:** a result up to about 30,000 characters comes back as is; a longer one is saved to a file, and the model
  gets the path and the first 2,000 characters. A failed command gets an excerpt of its start and its end.
- **Read:** up to 25,000 tokens per call. A longer file comes back as its first page with a "PARTIAL view" notice
  (which lines, how many in all, how to read on with `offset` and `limit`).
- **Grep:** `offset` and `head_limit` page the results.

Our loop stops a task before a prompt passes 80,000 tokens (to stay clear of the 5x price above 100,000), so our page
is smaller: 40,000 characters, twice the old cut. Every ticket in the benchmark fits in one read.

## Step 3: build the budget

Open `agent/tools.py`:
- the limits: `INLINE_MAX` 30,000, `PREVIEW` 2,000, `FAILED_MAX` 10,000, `PAGE_MAX` 40,000, `WHOLE_MAX` 256 KB;
- `fit()`: a longer result goes to `.outputs/<tool>-NNN.txt` in the project; the model gets the path and a preview;
- `ends()`: a failed command keeps its first and last 5,000 characters (exit 1 of `grep`, `find`, `diff`, `test` and
  `[` isn't a failure);
- `read_file()`: pages of up to 40,000 characters and 2,000 lines, with the note when the file goes on; a range over the
  page is refused, saying how many lines fit; a whole file over 256 KB is refused (read a part, or search it);
- `search_files(offset=...)`: the next 100 results.

```bash
uv run pytest -q tests/test_context_budget.py      # 15 tests, offline
uv run python -c "from agent.tools import *; print(read_file(Path('bench/tasks/t06-reminder-text/start'), 'tickets/T-2302.md')[-240:])"
uv run python -c "from agent.tools import *; print(read_file(Path('bench/tasks/t09-leave-rota/start'), 'logs/booking-2026-10.log')[-560:])"
```

What to look for: the ticket ends on line 359, with no cut. The booking log (1,912 lines) comes back as lines 1-570 and

limit=570 for the next page ...]`. If you see `more characters cut` instead, you're still on `ep02`.

## Step 6: what did the work

In the 45 tries, a result was saved to `.outputs/` four times, and the model never read one back: it ran a narrower
command instead, or left the saved files out of its search (`glob=!.outputs/**`). One file came back as a page with
the note (`clinic.json`, in a t01 try); the model didn't need the rest. So the page size did the work: every ticket now
fits in one read. Look for these in your own run: `Output too large` and `[PARTIAL view` in the tool results, and
`offset=` in the calls.
