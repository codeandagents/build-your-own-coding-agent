# Episode 2: Claude Code's tools

Follow-along for **Build Your Own Claude Code**, episode 2 ([video](https://www.youtube.com/@CodeAndAgents)). Same
setup as [episode 1](ep01.md). The episode's harness is the tag `ep02`; each step has a tag of its own:

| Tag | What it adds | Tries | Score |
|---|---|---|---|
| `ep02-tools-only` | `read_file`, `write_file`, `edit_file` | 90 | 61 (60 counted: see step 2) |
| `ep02-steer` | one sentence in bash's description: use the file tools, not cat, sed or scripts | 90 | 61 |
| `ep02-search-lines` | `search_files` and `find_files`, first version (always prints lines) | 45 | 28 |
| `ep02` | search with Claude Code's output modes and ripgrep's `!` globs | 90 | 54 |

Your runs will differ in the details: the model doesn't answer the same way twice.

```bash
git checkout ep02
uv sync
uv run pytest -q                                   # offline, no key
```

**Read this first:** the agent runs shell commands on your computer, with placeholder rails only until episode 4's
sandbox. Start runs from a folder with nothing private in it: an agent's `cd -` goes back to the folder you started
from (see step 2).

## Step 1: the file tools

Open `agent/tools.py`: `read_file` (line numbers; `offset` and `limit` for ranges; the same 20,000-character cut as
bash), `write_file`, and `edit_file` (exact string replace: `old_string` must match exactly and occur once, or set
`replace_all`; a refusal says how to fix it). All three use UTF-8, keep a file's own line endings, and refuse paths
outside the project.

```bash
uv run pytest -q tests/test_file_tools.py tests/test_search_tools.py     # 45 tests, offline
```

## Step 2: the file tools alone

```bash
uv run python -m bench.board results/ep02-tools-only.jsonl results/ep02-tools-only-r4-6.jsonl
```

61 of 90. One pass doesn't count: in task t10's sixth try, the agent ran `cd ~-`, which took it back to the folder the
benchmark had been started from, a folder that held notes describing the task's hidden check, and it read them. So,
60 of 90. In the logs, the model called a file tool 43 times and the shell 866 times; 94% of its shell commands
chained several steps.

Count it in your own run: file-tool calls are logged as `> name(...)` lines, bash commands as `$ ` lines.

```bash
git checkout ep02-tools-only
uv run python -u -m bench.run --repeat 3 --label tools > tools.log 2>&1
grep -c "^> " tools.log; grep -c '^\$ ' tools.log
```

## Step 4: search

Open `agent/tools.py` again: `search_files` (a regular expression; `output_mode` files_with_matches by default, or
content, or count; `glob`, with `!` to leave files out) and `find_files` (a glob), both capped at 100 results with a
count of the rest. bash's description now steers searching to them too.

```bash
uv run python -m bench.board results/ep02-search-lines.jsonl                 # the first version, 45 tries
uv run python -m bench.board results/ep02.jsonl results/ep02-r4-6.jsonl      # the final one, 90 tries
```

54 of 90: no gain. It searched in 45 of 90 tries, asked for the matching lines in 36 of 57 searches, and never
searched in t09 or t10.

## Step 6: the search that came closest

Run the agent's own search from task t06's fourth try, through the same tool, on the task's starting files:

```bash
cd bench/tasks/t06-reminder-text/start
PYTHONPATH=../../../.. uv run python -c "from agent.tools import *; print(search_files(Path('.'), r'^\*\*[A-Z]|call|ampersand|wording|decid', 'tickets/T-2302.md', output_mode='content'))"
```

117 matches: the first 100 fill the output past the 20,000-character cut, and the 17 not shown include the decision
(line 239). Now the grep the harness blocked (the agent started it with `cd /`):

```bash
grep -n "^\*\*" tickets/T-2302.md; grep -n -i "call\|ring\|&\|ampersand\|wording" tickets/T-2302.md | grep -v "we'll call you, or ring Harbourside" | cut -c1-300
```

One screen, and line 239 is in it: "Agreed with the vets this morning: Anna's "call" instead of "ring", and "Txt STOP"
instead of "Reply STOP"".
