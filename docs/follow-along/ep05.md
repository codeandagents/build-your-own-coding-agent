Without the flag, the window is 64,000 tokens.

## Step 1: why the window fills

Every turn, the loop sends the whole conversation again: the task, every tool call and every output. On this
benchmark's files, Claude Haiku 5.5 counts about 1.7-2.4 characters a token, so task t06's ticket
(`tickets/T-2302.md`, 32.6 KB) is about 20,000 tokens once `read_file` returns it: more than half of a 32,000-token
window. One search later, t06 is past the window on its second turn.

```bash
uv run python -m bench.run --tasks t06 --window 32000 --compact none --brief    # live: a fraction of a cent
```

Look for `[context: N tokens, past the 32,000-token window]`, then `FAIL (context_limit, ...)`. Not every try reaches
it: in each of our runs, two of t06's three tries did.

```bash
uv run python -m bench.board results/ep04.jsonl | tail -1        # 35/45
uv run python -m bench.board results/ep05-none.jsonl | tail -1   # 29/45: 11 tries stopped at the window, 5 of them after their work was done
```

## Step 2: Claude Code's way

From Claude Code's docs ([how Claude Code works](https://code.claude.com/docs/en/how-claude-code-works), "When context
fills up"; [explore the context window](https://code.claude.com/docs/en/context-window)):
- "It clears older tool outputs first, then summarizes the conversation if needed. Your requests and key code snippets
  are preserved; detailed instructions from early in the conversation may be lost."
- The summary keeps "your requests and intent, key technical concepts, files examined or modified with important code
  snippets, errors and how they were fixed, pending tasks, and current work".
- Afterwards it "re-reads up to five of the files Claude has read or edited in the session, choosing the ones modified
  most recently. A file over 5,000 tokens comes back as a path reference without its content."
- If one output refills the window after each summary, it "stops auto-compacting after a few attempts and shows an
  error instead of looping".
- With Claude Haiku 5.5 (a 1M window) it compacts "at about 967K tokens by default"; `/autocompact` moves that line
  ([model config](https://code.claude.com/docs/en/model-config)).

The API has both steps as (beta) features: [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)
clears old tool results, and [compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) summarizes
(its threshold trigger is at least 50,000 tokens). This episode builds them in the harness instead.

## Step 3: clear old outputs

Open `agent/compact.py`, `clear_old_outputs()`: every tool result except the newest three (`KEEP`) that is 500
characters or longer becomes `[Cleared to save context: the output of read_file(tickets/T-2291.md), 35,167 characters.
Run it again if you need it.]`. The model's own text and tool calls stay. Its thinking blocks after the first changed
message are dropped: on Claude Haiku 5.5 a thinking block is valid only while everything before it is unchanged.

In `agent/loop.py`, after each turn's tool results, `size()` asks the API's free `count_tokens` how long the next
request will be. Past the window: `none` stops; otherwise clear, and carry on if it fits; `clear` stops if it doesn't.

```bash
uv run pytest -q tests/test_compaction.py                          # 13 passed, offline
uv run python -m bench.board results/ep05-clear.jsonl | tail -1    # 33/45
uv run python -m bench.run --tasks t07 --window 32000 --compact clear --brief   # live, about a cent
```

Look for `[cleared N old tool outputs: ...]` and the agent's next words. In our runs, after most clearings the agent
said it hadn't read the file or had worked "blind", and read it again; once (t07, try 2 of `results/ep05.jsonl`) it
said "I haven't actually read its contents yet" about the ticket its first words had summed up.

## Step 4: summarize

`SUMMARY` in `agent/compact.py` asks for the six things Claude Code's summary keeps, with "the exact snippets, values
and wording the task depends on (quote them)". `summary_request()` adds it after the last tool results (nothing earlier
changes); `restart()` starts a new conversation from the task, the summary and the files read or edited most recently
(up to five, within an eighth of the window; one that doesn't fit is only named). `loop.py` stops a task whose window
fills again right after three summaries in a row (`THRASH`).

```bash
uv run python -m bench.run --tasks t06 --window 32000 --brief    # live: a cent or less
```

Look for `[summary: the conversation starts again ...]` and the `summary:` lines. In our full run, t06's two summaries
both passed: try 3's quoted the final wording, and the agent went straight to the code; try 2's kept only where the
wording was ("the 9 Oct comment"), and the agent read the whole ticket again.

## Step 5: the score

```bash
for r in ep05-none ep05-clear ep05; do uv run python -m bench.board results/$r.jsonl | tail -1; done
```

29, 33, 32. On the four tasks the window cuts off (t06, t07, t10, t11): 7, 10 and 11 of 12 (episode 4: 12). The other
eleven: 22, 23, 21 of 33: their old failures (t04, t12, t15) and noise (t08, t09; the two tries the full run lost there
never reached the window). The two summary requests cost about a cent together.
