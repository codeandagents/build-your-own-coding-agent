# Episode 1: a coding agent is a loop

Follow-along for **Build Your Own Claude Code**, episode 1 ([video](https://www.youtube.com/@CodeAndAgents)).
The code is this repository at the tag `ep01`. Every command below is one the video runs; the output you get will
differ in the details, because the model doesn't answer the same way twice.

## What you need

- Python 3.12 or newer and [uv](https://docs.astral.sh/uv/)
- bash: on Windows, Git Bash (Git for Windows); the agent's shell runs through it
- An Anthropic API key for the agent's runs (the offline tests and the scoreboard need none)

```bash
git clone https://github.com/codeandagents/build-your-own-coding-agent
cd build-your-own-coding-agent
git checkout ep01
uv sync
uv run pytest -q                         # the harness's own tests: offline
export BYOCA_API_KEY=your-key-here       # or ANTHROPIC_API_KEY
uv run python -m bench.run --plan        # free: token counts and the estimated cost
```

**Read this first:** the agent runs shell commands on your computer. Episode 1's harness has placeholder rails only
(see `agent/tools.py`); a real sandbox comes in episode 4. If you're unsure, use a virtual machine or a container.

## Step 1: read the loop

Open `agent/loop.py`. Look for:
- `SYSTEM`: the whole system prompt, three sentences;
- `request()`: what each turn sends (system prompt, tools, the conversation so far, prompt caching, effort low);
- `run()`: send, append the reply, stop if it asked for no tool, else run each tool call and send the results back;
- `MAX_TURNS` and `PROMPT_CEILING`: the two limits that stop a runaway.

## Step 2: read the one tool

Open `agent/tools.py`: `TOOLS` (the definition the model sees), `run_tool()` (blocked patterns, 60-second timeout,
output cut at 20,000 characters), `tool_env()` (no keys in the agent's shell, `HOME` = its own folder).

## Step 3: read the spend guards

Open `agent/llm.py`, `Claude.create()`: the budget and per-run checks before each request, the cassette saved
before a reply is used, and the ledger line after it. Settings: `.runs/config.json` (`budget_usd`, default 5).

## Step 4: run it on one task

```bash
cat bench/tasks/t01-last-slot/task.md                # the task, word for word
uv run python -m bench.run --tasks t01 --brief
```

What to look for: the files it reads first, the moment it names the cause, the tests it runs, and the
`=== t01-last-slot: PASS` line. That line is the hidden check: tests the agent never saw, copied in to score it.
The work copy stays on disk: its folder is on the first line of the run.

## Step 5: check that the tasks are fair

```bash
uv run python -m bench.selfcheck t01 t06
```

For each task: at the start, the project's tests pass and the hidden check fails; with the reference fix, all pass.
No model is called.

## Step 6: the baseline

```bash
uv run python -m bench.board results/ep01.jsonl      # the episode-1 scoreboard (no key needed)
uv run python -m bench.run --tasks t06 --brief       # a task it fails
```

Then see why:

```bash
cd bench/tasks/t06-reminder-text/start
wc -c tickets/T-2302.md
grep -b -m 2 'Txt STOP' tickets/T-2302.md | cut -c 1-90
```

The ticket is 32,595 characters; the wording the vets agreed starts at character 27,151. The tool cuts every output
at 20,000.

To run the whole benchmark yourself (15 tasks, 3 tries; the `--plan` estimate first):

```bash
uv run python -m bench.run --repeat 3 --label mine
uv run python -m bench.board mine
```
